# Установка Hermes клиенту

Используй этот навык, когда владелец пишет:

- «установи Hermes моему клиенту»;
- «установи Hermes клиенту»;
- «установи агента по IP и паролю»;
- «разверни Hermes на новом VPS».

Кто есть кто в этом навыке:

- **Владелец** - твой хозяин, тот, кто пишет тебе и ставит задачу. Ему ты отчитываешься и у него спрашиваешь подтверждения.
- **Клиент** - хозяин сервера и будущего агента. Будущий агент должен отвечать только ему.

Цель: самостоятельно установить официальный Hermes Agent на сервер клиента, подключить Telegram и нейросеть, проверить работу и передать понятный итог. Владелец агента не вводит серверные команды вручную.

## Что запросить

Нужны:

1. IP-адрес сервера.
2. Логин, обычно `root`.
3. Временный пароль сервера.
4. Кто клиент, то есть хозяин будущего агента.
5. Числовой Telegram ID клиента. По нему агент будет отвечать только клиенту. Если ID не передали вместе с доступами, попроси его до подключения Telegram.
6. Токен Telegram-бота клиента. Он понадобится позже, перед подключением Telegram.

Для установки используй только официальный Hermes:

`https://github.com/NousResearch/hermes-agent`

Не проси постоянный пароль клиента. Сразу предупреди, что временный пароль нужно поменять после установки.

## Правила работы с паролем

- Не повторяй пароль в ответах.
- Не добавляй пароль в итоговый отчёт, инструкции и постоянную память.
- Не сохраняй пароль в проект, Git или обычный текстовый файл.
- Не передавай пароль в аргументе команды, если доступен более безопасный способ ввода.
- После завершения удали временные файлы с реквизитами.
- В финале обязательно попроси клиента заменить пароль через панель хостинга.

Обычный чат не является защищённым хранилищем. Не утверждай, что удаление сообщения удалило пароль из всех журналов.

## Порядок работы

### 1. Сначала только проверка

До установки:

1. Проверь подключение к серверу.
2. Определи операционную систему и архитектуру процессора.
3. Проверь память, свободное место, наличие `systemd` и обязательных программ из актуальной инструкции Hermes.
4. Проверь неработающие службы, открытые сетевые порты и запущенные прикладные процессы.
5. Проверь, нет ли уже установленного Hermes или другого важного проекта.
6. Получи актуальную официальную инструкцию и последний стабильный релиз из `NousResearch/hermes-agent`. Локальную копию не считай актуальной без проверки даты или commit SHA.
7. Верни владельцу короткий отчёт простыми словами.

На этапе проверки используй только команды, которые читают состояние. Не запускай `hermes setup`, `hermes doctor` и другие команды, если они могут создать конфигурацию или служебные файлы.

Сервер нельзя считать пустым, если на нём найдены пользовательские сайты, базы данных, боты, агенты, рабочие каталоги или прикладные systemd-службы. Обычные системные службы Linux сами по себе не означают, что сервер занят.

Не начинай установку без подтверждения, если:

- сервер не пустой;
- сервер не подходит под официальные требования;
- обнаружен работающий сайт, бот, база или другой проект;
- уже установлен Hermes, а владелец не выбрал: обновить его, создать отдельную установку или остановиться;
- официальный способ установки изменился;
- подключение нестабильно;
- непонятно, кто будет оплачивать нейросеть.

Если у выданного пользователя нет административных прав, не называй это автоматическим отказом. Проверь, возможна ли официальная установка в его домашнюю папку. Отдельно перечисли действия, для которых всё равно понадобится администратор: системные библиотеки, автозапуск после выхода пользователя или настройка сети.

Формат ответа:

```text
Сервер доступен: да / нет
Подходит для Hermes: да / нет
ОС и архитектура: ...
Память и свободное место: ...
Что уже находится на сервере: ...
Что будет установлено: ...
Что понадобится от клиента: ...
Можно начинать: да / нет
```

### 2. Установка

После подтверждения:

1. Установи последний стабильный релиз Hermes официальным способом. Используй стабильный канал, явные пути установки и Hermes home внутри домашней папки рабочего пользователя.
2. Не устанавливай случайные форки и копии репозитория.
3. Задай `TMPDIR` внутри домашней папки рабочего пользователя, чтобы временные файлы установки не оставались в общей системной папке.
4. Внутри сервера создай отдельное рабочее место для Hermes, чтобы он не работал под главным администратором без необходимости.
5. Проверь, что команда Hermes запускается из установки этого пользователя, а не из старой глобальной копии.
6. Не запускай gateway вручную перед установкой службы. Если уже работает неуправляемый gateway, сначала остановись и выясни его назначение, иначе два процесса будут конфликтовать.
7. Настрой автоматический запуск после перезагрузки.
8. Не открывай наружу внутренние панели управления и служебные порты.
9. Запусти официальную диагностику Hermes.

До установки сохрани список файлов в домашней папке. После установки сравни его с новым списком и перечисли изменённые корневые каталоги. Не включай содержимое секретных файлов в отчёт.

`hermes doctor` может вернуть ненулевой код до подключения нейросети и Telegram. Не называй установку сломанной только по коду выхода: раздели критические ошибки, ожидаемые предупреждения без авторизации и предупреждения о зависимостях. Не запускай автоматическое исправление без отдельного решения владельца.

Не отправляй владельцу поток технических команд. Сообщай только этап, результат и проблему, если без решения владельца продолжить нельзя.

### 3. Подключение нейросети

Предпочитай вход по ссылке или одноразовому коду.

Клиент сам входит в свой аккаунт выбранного сервиса. Варианты по официальной документации Hermes:

- **Подписка ChatGPT (Codex) или Nous Portal** - вход по одноразовому коду. Основной вариант.
- **API-ключ** (Anthropic, OpenRouter и другие) - оплата за фактический расход. Попроси клиента поставить лимит расходов в своём аккаунте.
- **Подписка Claude** - по документации Hermes работает только на тарифе Max с докупленными дополнительными кредитами. Расход списывается из этих кредитов, а не из лимита Max. На тарифе Pro не работает. Перед подключением предупреди об этом владельца и предложи API-ключ, если докупленных кредитов нет.

Никогда не проси:

- пароль от аккаунта;
- пароль от почты;
- код двухфакторной защиты;
- данные банковской карты.

### 4. Подключение Telegram

Основной путь:

1. Клиент создаёт бота в своём `@BotFather`.
2. Получает токен, то есть пароль от бота.
3. Передаёт токен для подключения.
4. Ограничь доступ Telegram ID клиента.

Если Hermes сообщает, что модуль Telegram не установлен, используй официальный менеджер Hermes: `hermes pm install --extra telegram`. Не ставь случайные Telegram-пакеты через системный `apt` или глобальный `pip`.

Если доступна официальная кнопка Hermes `Create with QR`, предложи её как более простой вариант только после проверки, что клиент сможет открыть её без терминала.

Токен не показывай в ответах и отчётах. При утечке попроси клиента создать новый токен через BotFather.

### 5. Проверка

Установка готова только после реальных тестов:

1. Hermes запущен.
2. Telegram-бот отвечает клиенту.
3. Посторонний Telegram-пользователь не получает доступ.
4. Агент выполняет тестовую задачу с проверяемым файлом.
5. Агент сохраняет и вспоминает простое правило о клиенте.
6. Агент работает после перезагрузки сервера.
7. Создана резервная копия или передана проверенная инструкция её создания.
8. Клиент знает, где оплачивает сервер и нейросеть.

Пункты про Telegram нельзя закрывать только по статусу «Connected». В боевой установке отправь реальное входящее сообщение от клиента и отдельно проверь отказ пользователю, которого нет в разрешённом списке.

По каждому пункту ставь статус:

```text
проверено / не проверено / не работает
```

Не пиши «готово», если обязательный пункт не проверен.

### 6. Передача

В финале:

1. Дай клиенту имя Telegram-бота.
2. Объясни, где оплачивается сервер и нейросеть.
3. Дай одну простую инструкцию остановки и запуска через запрос агенту.
4. Объясни, что делать, если агент не отвечает, и как сменить токен бота через BotFather, если он попал к чужим.
5. Создай полный backup Hermes, проверь отчёт о пропущенных файлах и сразу установи архиву права `0600`.
6. Предупреди, что полный backup содержит `.env`, `auth.json` и другие секреты, но не содержит user systemd unit. Не отправляй такой архив в обычный чат.
7. Сообщи владельцу, остался ли у тебя постоянный доступ к серверу: добавленный SSH-ключ или другой способ входа без пароля. Если остался, а владелец не договорился с клиентом о поддержке, убери его и подтверди, что убрал. Смена пароля такой доступ не закрывает.
8. Попроси клиента поменять временный пароль сервера.
9. После смены пароля попроси проверить Telegram-бота ещё раз.

## Итоговый отчёт

```text
Hermes установлен: да / нет
Telegram подключён: да / нет
Доступ ограничен клиентом: да / нет
Нейросеть подключена: да / нет
Автозапуск проверен: да / нет
Работа после перезагрузки проверена: да / нет
Резервная копия: создана / не создана
Постоянный доступ установщика к серверу: нет / есть, по договорённости о поддержке
Что должен сделать клиент: ...
Известные ограничения: ...
```

## Запреты

- Не выдумывай успешную проверку.
- Не используй неофициальный репозиторий.
- Не удаляй существующие проекты клиента ради установки.
- Не отключай защиту сервера ради быстрого результата.
- Не обещай, что пароль исчез из всех журналов.
- Не оставляй временный пароль без напоминания о замене.
- Не оставляй себе постоянный доступ к серверу клиента без договорённости владельца с клиентом о поддержке.
- Не объявляй работу завершённой только потому, что установка закончилась без ошибки.
